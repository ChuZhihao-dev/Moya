## 实施解释（不是原文新增硬标准）

- A 将图片、音视频等统称为使用 loading="lazy"。实际实施应按元素与平台支持选择延迟加载方案，不给所有媒体机械添加同一个属性；关键首屏/LCP 图片不能被懒加载。需要时查当前官方文档确认实现。
- A 同时要求 Minify 与 gzip/brotli。自定义 JS/CSS 压缩由项目构建验证；传输压缩应通过实际 CDN/托管响应验证，不能把本地生成压缩文件等同于线上已启用，也不要声称主题代码能控制全部托管配置。
- “预加载关键资源”应根据实际首屏依赖选择，不预加载所有图片、字体或全部 CDN 资源；避免为了满足条款造成竞争。
- A 要求产品、集合、博客图片 Alt 未配置时用标题兜底。装饰性图片的空 Alt 与该要求可能存在可访问性边界问题；先区分图片用途，遇到冲突按项目决定记录，不能为装饰图编造商品描述。
- Product/Offers 随真实商品、价格、币种、库存更新；AggregateRating/Review 只输出真实存在的数据。无评论不是伪造评分的理由，应记录条件不适用。
- B 关于 FAQ 富媒体展示的文字是原文目标，不代表搜索引擎保证展示。实现真实可见 FAQ 对应的结构化数据；当前适用性、资格与字段要求在执行时查官方资料。
- B 其他 Page 的 URL 规则明确包括避免动态参数、中文、特殊符号。用于新建 URL 规划；不要据此擅自迁移已有 URL。已有地址调整需要评估重定向、内链等影响并纳入明确任务范围。
- 来源未给出自动化 CI、测试覆盖率、额外的 Web Vitals 数值、部署审批或报告固定次数。本 Skill 的记录流程属于执行方法，不冒充原文条款。
