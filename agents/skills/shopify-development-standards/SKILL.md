# Shopify 开发与验收规范

将规范贯穿设计、开发和交付。按本次任务的影响范围执行，不因小修改强制重做全站或引入无关功能。

## 开始工作

1. 读取项目 AGENTS.md、现有主题结构、构建与检查命令；识别传统 Shopify 主题还是已明确采用的 headless 项目。优先沿用当前主题与工具链。
2. 阅读 [来源与解释边界](references/source-notes.md)，以及 [开发条款](references/development.md) 中与任务有关的章节。涉及页面或 UI 时，再读 [页面 SEO 条款](references/page-seo.md) 对应页面类型。资料是 2026-10-22 的人工整理快照，不会自动同步飞书。
3. 列出受影响页面、组件和适用条款编号。新建 Section 前先确定复用样式、布局变体、动效及 Schema 配置方案。普通修复以本次影响范围为准。
4. 遇到规范冲突，先应用用户当前指示与明确的项目约定；没有明确约定时采用来源说明中的临时解释，并在交付中说明。对范围、成本或设计有实质影响的歧义，先询问，继续不受影响的工作。

## 实施

- 复用主题原有 Section/Block、CSS 变量和组件。非 headless 项目优先 Liquid/CSS/Vanilla JS；用 BEM 或项目前缀隔离自定义样式。
- 新组件考虑运营可配置和复用；不要把新组件要求变成对全部旧组件的重构要求。
- 按真实页面组合检查一个可见 H1、合理的 H2–H6、HTML 文本、可抓取链接和页面对应 Schema。单个 Section 正确不能替代整页验证。
- 保持“必须”“建议”“可选”的级别；不要把建议布局变成强制版式，也不要编造评论、评分、价格或库存。
- 性能要求按 DEV-11～DEV-15 实施。媒体、压缩与平台能力的解释见来源说明；遇到技术不确定性先查当前官方资料，不能机械添加无效属性。
- 实现任务不自动授权安装 App、修改商店配置、发布线上主题或进行其他外部变更；按用户已授权范围执行。

## 验证与交付

- 先运行仓库已有、与修改相关的检查（例如现有 Theme Check、构建）；仅在需要时补充检查。没有安装的工具如实标记，不能伪造命令结果。
- 在可访问预览中检查受影响页面、移动端与桌面端布局和交互；涉及 Section 配置时检查 Theme Editor 的配置与重复实例。全站交付覆盖所有适用条款。
- SEO 在最终 HTML/实际页面上验证；结构化数据解析成功与 Rich Results Test 无 Error 是不同证据。FAQ 或 Review 的 Schema 不等于保证搜索结果展示。
- 正式性能验收须在含商品、变体、评论及合规追踪的真实业务环境提供移动端 ≥60、桌面端 ≥80 的 Lighthouse 性能得分报告。记录 URL、时间、环境和配置；空页面或本地模拟结果只能作为阶段证据。来源没有单独规定 LCP/INP/CLS 数值，不自行编造硬门槛。
- 用 [验收记录模板](assets/acceptance-record.md) 记录编号、结果和证据。结果只用：通过、未通过、不适用、待验证。不适用必须说明原因；缺少访问、后台、真实数据或外部工具证据时使用待验证。
- 简述改动、已验证项、未通过项、待验证项和规范偏离；有未通过或待验证项时不得宣称完整验收通过。普通小修改可直接在回复给出相关编号与证据，无需每次生成整份报告。
